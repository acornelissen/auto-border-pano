# Porting the GUI to Qt

## Why

The design plan called this in advance:

> If the user later wants the version of this that feels genuinely crafted —
> precise hairlines at 2x, a strip that scrolls with momentum, a loupe that
> follows the cursor — that is a **PySide6/Qt** rewrite of the GUI layer.
> They have not asked for this and should not do it yet.

They have now asked for it, after two rounds of polish on the tkinter build
still left the interface reading as ugly. The diagnosis was specific:

1. **`clam`'s element rendering, not its colours.** A ttk combobox is built
   from `Combobox.downarrow` + `Combobox.field` — a bevelled button with a
   fat triangle welded to a bordered box. A button is `Button.border`, a
   hard 1px box. Recolouring never touches that vocabulary, and it is the
   thing that reads as decades old.
2. **A palette with no range.** `LIGHTBOX` #F1F4F6, `SLEEVE` #DCE1E4 and the
   strip were three values within a few percent of each other. No white, no
   dark surface. Everything sat in one narrow tonal band, so nothing had
   presence and the whole thing read as a wash. That was a design error
   independent of the toolkit: a palette picked for a concept, never checked
   for whether an interface could be built out of it.

Qt fixes (1) outright — QSS gives real control over how a widget is drawn —
and the palette below fixes (2).

## What moves and what does not

Untouched, and their tests keep passing unchanged: `geometry.py`,
`layout.py`, `compose.py`, `pipeline.py`, `cli.py`.

Rewritten: `gui/` only. `cli.gui_main` still imports `run` from the `gui`
package, so the entry point contract does not change.

## The concurrency model changes completely

This is the single most important thing to know when reading the ported
code, and it invalidates the old rule rather than restating it.

Under tkinter the rule was: *nothing on a worker thread may touch any tk
object, and `root.after()` is the only sanctioned crossing back.* Every
worker hand-rolled that crossing, and each one needed its own guard against
the window closing mid-flight.

Under Qt, a `QObject`'s signal emitted from a worker thread is **queued** to
the receiver's thread automatically. So a worker emits a signal carrying
plain data and Qt delivers it on the GUI thread. The rule becomes: *workers
own no widgets and emit signals; slots on the GUI thread do the widget work.*
There is no `after`, no manual marshalling, and no window-closed guard,
because Qt drops queued events for a destroyed receiver.

The stale-response problem does not go away and the token guards stay.

## Palette

Named for what they are in the room, and chosen to have actual range —
white through near-black — rather than three shades of the same grey.

| Token | Hex | Role |
|---|---|---|
| `TABLE` | `#FBFCFD` | The light table itself. Window background. |
| `PANEL` | `#EEF1F4` | The control rail, sitting slightly below the table. |
| `WELL` | `#FFFFFF` | Input fields. White, because a field you type into should be paper. |
| `EDGE` | `#D5DBE0` | Hairlines and dividers. One device pixel, which Qt can actually do. |
| `REBATE` | `#15171A` | Film base: the header band and the strip. |
| `INK` | `#14171A` | Primary text. |
| `INK_DIM` | `#5C646B` | Secondary text, 5.9:1 on panel. |
| `CHINAGRAPH` | `#C9302A` | The grease pencil. Primary action and errors, nothing else. |

`INK` on `TABLE` is 16.1:1. `INK_DIM` on `PANEL` is 5.9:1. `CHINAGRAPH` on
`TABLE` is 5.3:1 and inverts to white-on-chinagraph at 5.0:1. Every pairing
clears AA for normal text, which the old `SPROCKET` did not.

## What Qt buys that tkinter could not

- Hairlines that are one *device* pixel at 2x, not one blurry point.
- Real focus rings, hover and pressed states without hand-drawing them.
- `QGraphicsView` for the contact strip, with proper transforms.
- Widgets styled by stylesheet rather than by rebuilding element trees.
- Native accessibility, which the hand-drawn Canvas widgets had none of.

## Deliberately not doing

Rounded corners and drop shadows, even though Qt makes both trivial. The
direction is a light table and film rebate: both hard-edged. Qt removing a
constraint is not a reason to spend it.
